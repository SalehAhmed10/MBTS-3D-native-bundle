Current implementation (verified by reading source 2026-07-04):

`src/services/avatarBundleManager.js` — downloads a ~5MB core bundle (index.html, app.js, playback-worklet.js, manifest.json, all backgrounds) from Vercel on first launch to `FileSystem.documentDirectory + 'avatar-web/'`, version-gated via a `BUNDLE_VERSION` string written to `.bundle-version`. Each avatar's GLB (`AVATAR_GLBS` map: camilia/prithi/benjamin/john) downloads lazily on first selection via `downloadAvatarGlb()`, with a size-sanity check (rejects/redownloads anything under 50KB as corrupt) and progress callback. `preloadAllGlbs()` fires in the background after the core bundle is ready to warm the cache for avatars not yet selected.

`src/components/avatar/AvatarWebView.js` — on mount, checks `isBundleCached()`; if not cached, shows a download progress UI (`statusLabel: 'downloading'`) while `downloadCoreBundle()` runs, then does the same for the initial avatar's GLB. Once ready, resolves the WebView source to the local bundle URI (`getLocalBundleUri()`). The `setAvatar` imperative handle checks `isAvatarGlbCached` and calls `downloadAvatarGlb` before sending the `setAvatar` postMessage — this happens transparently for every avatar switch, not just Benjamin. Falls back to the hosted URL if bundle prep fails.

`avatar-embed/avatars/manifest.json` already contains camilia, prithi, and benjamin entries with camera settings and voice IDs (confirmed: benjamin has `am_fenrir` voice, `Benji.glb` url). John needs to be added following the same schema (this task).
